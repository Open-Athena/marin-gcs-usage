# CP manifest: `@disk-tree/react` core changes, 2026-08-28

Written from the disk-tree session. `specs/dt-core-upstreaming.md` says `Treemap.tsx` differs from upstream "only by `fadeFloor`" — no longer true after today; these are the upstream (`runsascoded/disk-tree` `main`) commits to bring across, oldest first. All in `packages/react/src/Treemap.tsx` unless noted; the tiling one also touches `index.ts`, `styles.css`, and `tests/Treemap.test.tsx`.

- `761602c` depth fade moves to a `.dt-treemap-bg` paint layer — label ink never fades (the fade was CSS `opacity` on the cell div, compounding down the subtree and dimming labels; now bg/hatch/stripes sit on a child layer with `opacity = fadeAt(depth) × style.opacity`, `fadeAt(d) = max(rootFade × depthFade^d, fadeFloor)` — no ratio compounding). This supersedes the `fadeFloor` scheme you had deferred.
- `e2af851` opaque container-color base per cell (`background: var(--dt-treemap-container-bg)`) — ancestor bg never bleeds into descendants through translucent children; it surfaces only in title bars and gutters.
- `489422e` `--dt-treemap-cell-border` — opt-in 1px outer ring in the gutter (gaps mode), default transparent.
- `5fdacbd` `renderCellSubtitle(n, path, dims)` — third arg is the cell box, so width-aware inline content can drop rather than crush the name.
- `c128ff0` **shared-edge tiling + depth-scaled borders** — implements your `specs/treemap-shared-edges.md`: `tiling?: 'gaps' | 'shared' | ((n, path, depth, ctx: TilingCtx) => Tiling)` (callback is called for the node whose children are being tiled, with `{w, h, nChildren, medianChildArea}` from a first layout), `borderWidth?: (depth, dims) => number` (default `max(1, 3 − depth)`, dust capped at 1px). Shared cells occupy exact rects, square corners, and draw *half* the stroke as an inset ring (`box-shadow: inset 0 0 0 bw/2 var(--dt-treemap-edge, container-bg)`) so each boundary is one stroke attributed half to each neighbor; children fill to the parent's half-stroke; makeup stripes inset to the stroke. Default remains `'gaps'` — identical output to before for existing consumers (tests pin both geometries). Not done from the spec: the overlay-labels (no reserved title bar) mode.

Suggested marin setting per your spec: `tiling={(n, p, depth, ctx) => ctx.medianChildArea < 100 ? 'shared' : 'gaps'}` — gaps at container levels, shared for leaf swarms. disk-tree's compare view uses plain `'shared'` with `--dt-treemap-edge: rgba(255,255,255,0.18)`.
